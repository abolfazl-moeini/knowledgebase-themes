Install Cumulus Omni using containers

Run Cumulus Omni as a set of containers on any host with Docker or Podman. This page walks through a single-node installation suitable for evaluation, development, and small production workloads.

Cumulus Omni is a distributed, PostgreSQL-compatible database that runs anywhere you can run a container. The container image is published to the official registry and is updated with each release. Omni is intended to be operated like any other stateful workload: with persistent storage, scheduled backups, and a clear upgrade path.

Before you begin

  • A Linux host with at least 4 vCPUs, 16 GB of RAM, and 100 GB of free disk.
  • Docker Engine 24+ or Podman 4.4+ installed and running.
  • Root or sudo access on the host.
  • A reserved TCP port range (default 5432, 6432, 8443).
Try Cumulus Free first

If you don't have a host available, the Cumulus Free tier provisions a managed Omni cluster in under a minute, with $300 in credit for new users. Create a free cluster →

Step 1: Pull the container image

Pull the latest stable image from the Cumulus registry:

docker pull registry.cumulus.cloud/omni:18.1.0

Step 2: Create a persistent volume

Omni stores its data in /var/lib/omni inside the container. Mount a host volume so the data survives container restarts:

docker volume create omni-data

Step 3: Start the container

Run the container with the recommended flags. Replace $OMNI_PASSWORD with a strong password of your choice:

docker run -d \
  --name omni \
  --restart unless-stopped \
  -p 5432:5432 \
  -p 6432:6432 \
  -p 8443:8443 \
  -v omni-data:/var/lib/omni \
  -e OMNI_PASSWORD=$OMNI_PASSWORD \
  registry.cumulus.cloud/omni:18.1.0

Step 4: Connect to the cluster

Once the container is healthy (typically 30–60 seconds), connect using the standard psql client:

psql -h 127.0.0.1 -p 5432 -U omni -d omni

You'll be prompted for the password you set above.

Verify the installation

Run SELECT version(); to confirm the cluster is reachable. You should see a banner that includes the Cumulus Omni version string.

What's next

  • Configure high availability — run a multi-node cluster
  • Schedule backups — point-in-time recovery to object storage
  • Monitor Omni — Prometheus metrics and Grafana dashboards
For production

The single-node setup on this page is suitable for evaluation and small workloads. For production deployments, use a multi-node cluster, enable TLS, configure scheduled backups, and set up monitoring. See the production checklist.
